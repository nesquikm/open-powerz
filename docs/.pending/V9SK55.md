## Firmware update (FR V9SK55)

- `firmwareChoose()` (new) opens the open dialog filtered to `.mencrypt` firmware containers. It
  resolves to the chosen path, or `null` when the dialog was cancelled.
- `firmwareFlash(deviceId, path, confirmation, onStage)` (new) updates the meter with the file at
  `path`. The backend holds the meter for the whole update, so connecting, PD capture, recording,
  the rate, the trigger and hotplug reconnects are refused until it ends. Before anything is sent,
  the backend checks that `confirmation` is the file's version and reads the file again. Each stage
  goes to `onStage` over a channel, with about one write message per percent. It resolves to a
  `FlashDone`, or rejects with the error. Closing the window or quitting the app is refused while an
  update runs.
- `FlashStage` (new): `switching`, `erasing`, `writing` (with `done` and `total` bytes),
  `verifying`, `finished` and `returning`.
- `FlashDone` (new): `verified` with the version read back from the meter, or
  `power_cycle_needed` when the image was accepted but the meter stays in its bootloader until it
  is replugged.
- `Session` has a `flashing` flag. While it is set, the device picker and Connect are disabled.
- `MockBackend` runs a synthetic update with every stage. `MOCK_MODES` adds
  `firmware-fail-switching`, `firmware-fail-erasing`, `firmware-fail-writing`,
  `firmware-fail-verifying` and `firmware-fail-returning` (fail at that stage),
  `firmware-other-model` (a KM002C file) and `firmware-bad-file` (a file that fails inspection).

The Firmware tab appears only when **Advanced firmware** is switched on in About. That switch is
stored in the browser and is off by default.
