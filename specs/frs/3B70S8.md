# The CLI watch over CDC exits while the browser streams

## Summary

The command-line watch over the serial port quit while a browser streamed over WebUSB.
The plain watch took a stray stream frame for its answer.
The stream watch gave up because the meter kept echoing its start.
Now each request takes only its own reply and skips the rest.
The stream watch falls back to plain readings instead of quitting.

## Requirement

### Steps to reproduce
1. Stream from the meter in the web edition over WebUSB.
2. Run the CLI watch over the CDC transport, with the default source and with the CDC source.

### Expected
Both keep showing readings until stopped.

### Actual
The default source exits with "unexpected reply to GET_DATA: Unknown(2)"; the CDC source exits after about 25 to 40 s with "the meter keeps echoing the ADCNEW start instead of streaming" (web parity HIL 4, P6).

## Acceptance Criteria

- AC-3B70S8.1: Regression: over the CDC transport, a request's reply is the frame carrying its id; ADCNEW frames, an echoed stream start, text lines and replies to other ids that arrive before it are skipped, also when no ADCNEW stream was started.
- AC-3B70S8.2: The CLI watch with the default source keeps running and prints fresh readings when such frames sit between its replies.
- AC-3B70S8.3: The CLI watch with the CDC source, once the meter echoed the start more than the echo limit, prints one note to standard error and goes on with ADC snapshots on the same port, in the same line format, until stopped.
- AC-3B70S8.4: The CLI stream with the CDC source keeps its behaviour and still gives up after the echo limit.
- AC-3B70S8.5: The protocol doc and the CLI docs describe the skipped frames and the watch fallback.

## Technical Design

### Root cause
The CDC transport reads through the demux only after an ADCNEW start, so a stray frame starting with 02 becomes a four-byte control frame of type 2. The meter echoes ADCNEW starts as long as a bulk session runs.

### Fix
The plain request path takes only the reply carrying the request's id and skips stream frames, echoed starts, text lines and other replies, leaving later bytes raw for memory-read follow-ups (the demux would consume them). The CDC watch loop switches to snapshots once the echoes pass the limit.

## Testing

Fake-port tests in the CDC transport; CLI tests over the simulator and a scripted port for both watch sources and the unchanged stream.
