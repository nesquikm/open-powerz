# README lists what open-powerz does

## Summary

The project page still says the app is in early development and talks to no device.
That stopped being true several releases ago.
The README should state the real status and list every shipped feature, each linked to its guide.
A check keeps the list from going stale again when new features ship.

## Requirement

The README states the current status and lists every shipped feature of the CLI and the desktop app, grouped by area and linked to its documentation, and a gate check fails when a shipped feature is missing from it.

## Acceptance Criteria

- AC-7V4B90.1: The status line describes the real state: working desktop app and CLI, tested on a real KM003C, unsigned builds, KM002C untested. The "Nothing talks to a device yet" line and the "Planned features" list are gone.
- AC-7V4B90.2: A Features section lists every shipped feature grouped by area (live meter, recorder and charts, PD analyzer, protocol triggers, firmware update, offline records, meter settings, serial stream, several meters, CLI, demo device and simulator, releases). Each item is one line, names what the user can do, and links to its how-to or reference page where one exists.
- AC-7V4B90.3: A short "Coming next" list names the planned work (record delete and settings writes, polish, the browser edition) without dates.
- AC-7V4B90.4: The README shows at least one screenshot of the desktop app, taken with the demo device so no real serial number appears; the image lives in the docs folder and is small enough for a fast page load.
- AC-7V4B90.5: The License section says the AES keys are shipped (present tense), and nothing else in the README describes shipped work as future.
- AC-7V4B90.6: A gate check fails when a CHANGELOG "Added" entry's feature has no matching README Features line, using a small mapping file kept next to the check, with tests for a covered and a missing feature.
- AC-7V4B90.7: Every relative link in the README resolves to a file in the repository, checked by the gate.

## Technical Design

Rewrite the README sections in place; keep Install, Layout, Building and Try it without a meter. The coverage check is a small script with a mapping from CHANGELOG feature ids to README anchors, run by the existing test gate. The screenshot is taken from the mock build with Playwright.

## Testing

Unit tests for the coverage and link checks. A visual look at the rendered README on GitHub after the merge.
