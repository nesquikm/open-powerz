# Whole-session view: session time, gaps and axes

## Summary

After an unplug, the whole-session view labelled time with the meter's own clock.
It also drew a line straight across the forty minutes without data.
Time now counts from the session start in every view, written as seconds, minutes or hours.
Every break between runs breaks the lines and is shaded with its length.
Value axes are wide enough for their labels, and every spike stays visible at any zoom.

## Requirement

The chart labels time from the session start, breaks and shades every stretch without data (including breaks between connections the backend recorded before the current one), sizes its value axes to their labels, and draws a min/max envelope at every zoom.

## Acceptance Criteria

- AC-272WSN.1: The time axis counts from the session start, never from the meter's own clock, in every view; it writes seconds under a minute, m:ss under an hour and h:mm:ss beyond, with ticks on round session times (seconds and minutes steps, never 50 s or 50 min).
- AC-272WSN.2: The hover readout and the screen-reader range announcements use the same session-relative time as the axis.
- AC-272WSN.3: The backend reports every break between measuring runs of the session history (an unplug, a user disconnect and reconnect, a clock jump), including runs before the current connection, through a command that returns the breaks overlapping a time range.
- AC-272WSN.4: No line crosses a break between runs or a stream gap in any view, including "Whole session" after a reconnect.
- AC-272WSN.5: Each stretch without data in view is shaded, with a "No data · <length>" label when the label fits inside it.
- AC-272WSN.6: Each value axis is as wide as its widest tick label, so its title never covers a label.
- AC-272WSN.7: At every zoom, including "Whole session", each pixel column is drawn from the min and max of the samples it covers, so a single-sample spike stays visible.

## Technical Design

The history already marks where runs start; it now reports each break as a span from the last record before to the first after (history_gaps command). The chart fetches these beside every history_range answer into its gap list, merged with a stream gap event when the two overlap by at least 90 percent. Time labels subtract the session origin: the history's first sample, else the first buffered one. The time axis uses its own tick steps, splits counted from that origin and one style per axis. Gap bands are painted under the series in uPlot's drawClear hook. Value axes size themselves from the measured width of their longest label. The envelope reuses the existing two-points-per-pixel reduction and min/max buckets.

## Testing

Rust: the history gap query and a reconnect on one store (history.rs), and a user disconnect through the device manager (devices.rs). Vitest: tick labels, splits and steps, time and duration formatting, axis sizing (chartSeries), gap list overlap, deduplication, bands and spike survival (chartData), the history_gaps command (backend) and the outage mock (mockBackend). Playwright: session.spec.ts against the outage mock, which starts at a long meter uptime and is gone for 40 minutes.

## Notes

From the milestone hardware review: the axis read 30400 s to 32600 s and a dashed IBUS line bridged a 40-minute outage. A user disconnect raises no outage event, so the gaps come from the history itself.
