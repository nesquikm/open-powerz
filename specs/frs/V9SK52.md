# Device mode and firmware version

## Summary

Before any firmware work the app must know what is on the meter.
This feature tells normal mode from bootloader mode and reads the application and bootloader versions.
It warns when the firmware is old or when the meter itself reports that an update is required.
Everything here only reads from the meter.

## Requirement

The library, the command line tool and the desktop app report the meter's mode (application or bootloader) and its application and bootloader versions, and warn about outdated firmware, using read-only requests only.

## Acceptance Criteria

- AC-V9SK52.1: The library reports application mode or bootloader mode from the USB interface string (string 2, `APP` in application mode), and an unknown string as unknown.
- AC-V9SK52.2: In application mode it reads the bootloader and application info blocks at the documented safe addresses and reports model, version and date for each.
- AC-V9SK52.3: The old-firmware check reads the HEAD reply after CONNECT. In application mode a field of 0 means the firmware is current; any other value is shown as an unrecognised reply with the field and the raw bytes, and never as "update required" until its meaning is confirmed on the device.
- AC-V9SK52.4: Firmware older than 1.7.0, or older than the newest version the app knows of, shows a warning in the desktop app and in the command line tool's info command.
- AC-V9SK52.5: The desktop app shows the mode and both versions in the device details, and a meter found in bootloader mode is listed as such instead of failing to connect.
- AC-V9SK52.6: On the real meter in application mode the reported versions match the meter's About screen (app 2.0.6, boot 2.5 at the time of writing), recorded in the Notes.

## Technical Design

A mode probe reads the vendor interface's string from the OS device list, without opening a session. The info blocks come from the existing safe memory-read path. HEAD is a read-only request sent after CONNECT, as the vendor app does. The blocks are read before HEAD. A step that fails is shown as a problem, followed by one reconnect, and what was read is kept; only an unplug or a permission error still fails. A meter in bootloader mode is never opened, neither by hand nor on reconnect.

## Testing

Unit tests for the info-block and HEAD parsers, simulator tests for both modes, and a Playwright test for the device details. The real-meter check is manual.
