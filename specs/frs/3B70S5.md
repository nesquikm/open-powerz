# A wheel scroll up in a live PD capture can snap back to the bottom

## Summary

While a PD capture runs, the packet table follows new rows until you scroll up.
WebKit, which the macOS app uses, animates a wheel scroll in small steps.
New rows during the first step pulled the table back to the bottom.
Your scroll was lost.
Now a wheel scroll up pauses following at once.
The end-to-end test that caught this now passes reliably.

## Requirement

### Steps to reproduce
1. Start a PD capture with rows coming in, in the macOS app or Safari.
2. Scroll the packet table up with the mouse wheel.

### Expected
Following pauses and the table stays where you scrolled to.

### Actual
Sometimes the table jumps back to the bottom and Follow stays on (CI run 42683371695, macOS, WebKit: "Expected: false, Received: true" on Follow).

## Acceptance Criteria

- AC-3B70S5.1: Regression: a wheel event that scrolls the table up while it follows pauses following before the next rows arrive, whatever the scroll position after it; a table with nothing to scroll keeps following.
- AC-3B70S5.2: A wheel scroll down, or a wheel event while following is already paused, changes nothing, except that a wheel down at the bottom ends a wheel-up pause; reaching the bottom still resumes following as before, and Follow still resumes it.
- AC-3B70S5.3: The PD analyzer's follow test passes 20 runs in a row locally on WebKit and on Chromium with one worker.

## Technical Design

### Root cause
Following is judged from scroll positions only. The first frame of an animated wheel scroll stays within the 4 px bottom slack, so the next rows call the scroll to the end, which cancels the animation.

### Fix
The follow state gets a user-intent method that pauses following; the table calls it on an upward wheel, before any scroll event. Keyboard moves already pause through the row reveal. A view that cannot scroll ignores the wheel, and a wheel down at the bottom ends a wheel-up pause, since no scroll event comes then.

## Testing

Vitest on the follow state for the intent method; the PD analyzer spec repeated 20 times on both browsers.
