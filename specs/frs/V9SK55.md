# Desktop firmware update

## Summary

The desktop app gets a firmware update screen behind an advanced switch.
It shows the meter's current versions and the chosen file's version and release notes.
It asks for a typed confirmation before it starts.
During the update it shows each stage and blocks everything else that talks to the meter.
If anything fails, it explains how to put the meter into bootloader mode by hand and try again.

## Requirement

The desktop app updates the meter's firmware from a local file, behind an advanced switch and a typed confirmation, with progress, exclusive access to the meter and clear recovery steps.

## Acceptance Criteria

- AC-V9SK55.1: The firmware screen is hidden until an Advanced firmware switch is turned on in settings.
- AC-V9SK55.2: It shows the meter's mode and versions and the chosen file's metadata, and enables Update only when the file passes inspection and its model matches.
- AC-V9SK55.3: Update needs the user to type the target version to confirm, and warns to keep the meter connected and the laptop on power.
- AC-V9SK55.4: During the update the measurement stream, PD capture, triggering and device switching are blocked, and the screen shows each stage with progress.
- AC-V9SK55.5: On success it shows the new version read back from the meter. On failure it shows the error and the recovery steps (hold Back while plugging in, then retry).
- AC-V9SK55.6: The screen works with the keyboard alone, the axe check passes, and Playwright tests on the mocked backend cover success and a failure at each stage.

## Technical Design

A firmware view on the desktop backend's flash session. The backend takes exclusive ownership of the device for the update and releases it afterwards.

## Testing

Vitest for view state, Playwright with axe on the mocked backend, and worker tests against the simulated bootloader.
