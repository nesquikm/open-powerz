# The recording rows type lacks the TEMP field

## Summary

The browser edition's description of the rows an opened recording gives did not mention their temperature.
The reader in the shared code has returned it per row since the TEMP export fix.
Now the type says so, so code that reads the opened rows sees the temperature the reader gives.
Nothing on screen changes.

## Requirement

### Steps to reproduce
1. Read the web driver's recording rows type.

### Expected
Each row carries its TEMP, empty when the file's is.

### Actual
The type has no TEMP field, though the wasm reader returns one (v0.12.0 advisory).

## Acceptance Criteria

- AC-3B70S9.1: Regression: the recording rows type gives each sample a TEMP in degrees Celsius that is a number or null, and the typecheck passes.
- AC-3B70S9.2: A test reads a CSV with and without TEMP through the wasm reader and finds a number on the rows that have one and null on the others.

## Technical Design

### Root cause
The rows type reused the meter sample type, which has no temperature.

### Fix
Give the rows their own sample type: the meter sample plus a nullable TEMP.

## Testing

Vitest over the built wasm module and svelte-check.

## Notes

Advisory from the v0.12.0 ship.
