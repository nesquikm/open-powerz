# Desktop-only file action and old stats in the browser edition

## Summary

Two small rough edges showed up in the browser edition.
The toast for a saved recording offered "Reveal in Finder", which a web page cannot do.
The statistics panel kept the demo meter's numbers after connecting to a real meter, until the first real samples came in.
The browser toast now leaves out the file-manager actions, and starting a session on another device clears the statistics shown.

## Requirement

### Steps to reproduce
1. In the web edition, record from the demo meter and save the file.
2. Connect a real meter.

### Expected
The toast has no file-manager action; the statistics panel is empty until the meter's samples arrive.

### Actual
The toast shows "Reveal in Finder"; the panel keeps the demo's min, max and average (web HIL run WEB.hil2-20261108-2223, W5 and W2).

## Acceptance Criteria

- AC-R13Y5W.1: In the web edition the saved-recording toast shows no "Reveal in Finder" or "Show in folder" action and no copy-path action; the desktop toast is unchanged.
- AC-R13Y5W.2: When a session starts connecting on a device other than the one whose statistics are shown, the statistics panel is cleared at once, in the desktop app and the web edition.
- AC-R13Y5W.3: Reconnecting to the same device keeps the statistics behaviour it has today.

## Technical Design

### Root cause
The toast actions are not gated on the build's capabilities, and the panel keeps the last snapshot until a new batch replaces it.

### Fix
Gate the file-manager actions on a capability that is off in the web build; clear the shown snapshot when a connect begins on another device.

## Testing

Vitest on the capability map and the stats state; a component or e2e check of the toast in the web build.

## Notes

The "Startup logo" tab shown with Advanced firmware off is left for later; the orchestrator did not ask for it.
