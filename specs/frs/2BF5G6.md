# Windows CI fails on every failing command and runs green

## Summary

The Windows gate has been reporting green while its lint and one unit test failed.
Its multi-command steps ran in PowerShell, which keeps only the last command's result.
Every step now runs in bash, so each failing command fails its step.
Files keep Unix line endings on every platform, so Windows lint checks the real code.
A slow timing test and a racy replug test are fixed, and the Windows gate stays green.

## Requirement

### Steps to reproduce

1. Push any branch and open the log of the Windows gate job.
2. Read the step that runs lint, typecheck, unit tests and the web build.

### Expected

Any failing command fails its CI step, and the job goes red.

### Actual

Only the last command's exit code counts. On main run 39784216001, Windows lint failed on 113 files with Windows line endings. The 10-million-sample pan test timed out at 5 s. The job still passed.

## Acceptance Criteria

- AC-2BF5G6.1: Regression: a CI run step with several commands fails when any one of them fails, on every OS. A test reads the workflow and fails if this guard is removed.
- AC-2BF5G6.2: A step that sets its own PowerShell shell stops on the first error, and the workflow test checks this too.
- AC-2BF5G6.3: The repository keeps text files LF on every platform, so a Windows checkout has LF line endings.
- AC-2BF5G6.4: Windows lint passes in CI.
- AC-2BF5G6.5: The 10-million-sample pan test keeps its 100 ms pan budget and 5 s test timeout locally; on CI both are widened by the KQF5GM CI factor, and a failure names the budget it used.
- AC-2BF5G6.6: The replug recording test waits for the recording to start before it unplugs, and passes on Windows. None of its assertions is loosened.
- AC-2BF5G6.7: One commit is green on all 8 CI jobs, on the first run and on a re-run.

## Technical Design

### Root cause

GitHub runs a multi-line step on Windows in PowerShell, which reports only the last command's exit code. The step ran lint, check, test and build, so only the build counted. The repo has no line-ending attributes, so Windows checks out CRLF and Prettier flags it. Once failures surface, two latent issues show: the pan test needs more than 5 s there, and the replug test unplugs before recording starts.

### Fix

A workflow-level bash default, which runs with errexit and pipefail. Steps keeping PowerShell set the stop-on-error preference. A gitattributes file pins LF. The pan test takes its budget and timeout from the shared CI-factor helper. The replug test waits for the recording start event.

## Testing

A Vitest test reads the workflow: it asserts the bash default and that every PowerShell step stops on errors. It fails on the current workflow. The pan test runs strict locally and with the CI factor under CI. The replug test runs on all three OS gates. Evidence for AC.7 is a pair of CI run ids recorded in Notes.
