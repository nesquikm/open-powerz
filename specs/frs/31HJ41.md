# The Linux permission message points at a file AppImage users do not have

## Summary

On Linux without the udev rule, the app says to copy the rule file from the repository.
That file exists only in a source checkout, so AppImage users cannot find it.
Now the message carries a one-line command that writes the rule.
It also links to the Linux guide on the web.
The command line says the same.
The Debian package installs the rule itself.

## Requirement

### Steps to reproduce
1. On Linux without the udev rule, run the AppImage and connect a meter (or run `powerz devices` then any command).

### Expected
A message the user can follow without the source tree.

### Actual
`sudo cp packaging/linux/60-powerz.rules /etc/udev/rules.d/`, a path that does not exist outside a checkout.

## Acceptance Criteria

- AC-31HJ41.1: Regression: the desktop's Linux permission hint and the CLI's Linux permission error name no repository-relative path; each contains one shell command that writes a udev rule for vendor 5fc9 to the rules directory without reading any file, the reload and trigger commands, the replug step, and the full GitHub URL of the Linux guide.
- AC-31HJ41.2: The rule that command writes grants seat access (uaccess) and sets the ModemManager ignore flag for the meter's USB device, hidraw and tty nodes, matching what the shipped rule file grants.
- AC-31HJ41.3: The `.deb` bundle installs the shipped rule file into the system udev rules directory.
- AC-31HJ41.4: The Linux guide leads with the one-line command for release users, notes that the `.deb` installs the rule, and keeps the copy-from-checkout route for source builds; the install guide matches.

## Technical Design

### Root cause
`LINUX_PERMISSION_HINT` and `permission_error` were written for a source checkout.

### Fix
One shared constant in `powerz-protocol` for the inline command (`echo '<rule>' | sudo tee /etc/udev/rules.d/60-powerz.rules`) and the docs URL, used by `permission_error` and the desktop hint. The one-line rule matches on `ATTRS{idVendor}=="5fc9"` with `TAG+="uaccess"` and `ENV{ID_MM_DEVICE_IGNORE}="1"`. `tauri.conf.json` gets `bundle.linux.deb.files` mapping `/usr/lib/udev/rules.d/60-powerz.rules` to the packaging file.

## Testing

Unit tests on both texts (no `packaging/`, has the URL and the `tee` command); a test that the one-line rule covers the usb, hidraw and tty subsystems; a config test for the deb file map; existing hint and mock tests updated.

## Notes

The AppImage cannot install system files, so the inline command is its only route.
