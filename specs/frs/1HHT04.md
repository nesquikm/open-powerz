# Real-meter checks for meter data

## Summary

The new read features are checked on the real meter before the milestone ships.
The user first makes a short recording on the meter itself.
Fresh test agents then run written runbooks: list and download the recording, read the settings, and run the stream.
Results are compared with the meter's screen.

## Requirement

Offline records, settings read and the ADCNEW stream are checked on the real KM003C from runbooks, with results compared against the meter's screen, before the milestone ships.

## Acceptance Criteria

- AC-1HHT04.1: The user makes a recording of a few minutes on the meter (Settings, Storage); the runbook lists and downloads it, and its point count, duration, charge and energy match the meter's own record screen.
- AC-1HHT04.2: The decoded samples of that recording agree with the values the meter showed during it, closely enough to confirm the 16-byte sample fields.
- AC-1HHT04.3: The decoded settings are compared with a photo of the meter's display and dashboard settings.
- AC-1HHT04.4: The ADCNEW stream runs for at least two minutes at 50 and 1000 per second with no CRC errors, alongside a PDM text command, and its values match the bulk readout.
- AC-1HHT04.5: Each stage runs from a runbook written by the implementer and is carried out by a fresh test agent that only runs the runbook's commands; results go to the research workspace's QA folder and the FR Notes.
- AC-1HHT04.6: No command outside the allowed read set is sent (no delete, no settings write, no triggering above 5 V).

## Technical Design

One runbook per stage with preconditions, exact commands, expected output and abort criteria.

## Testing

Hardware only; results are recorded rather than automated.
