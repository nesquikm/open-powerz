# Device simulator and end-to-end tests

## Summary

We build a software copy of the meter, so the whole tool chain can be tested without hardware.
It answers requests like the meter, produces readings in real time, and can fake faults.
People can also use it on purpose as a demo device with named scenarios.
End-to-end tests run the real command-line tool against it on every platform.
An opt-in suite runs the same flows on a real meter.

## Requirement

Add a stateful simulated KM003C that implements the library's `Transport` trait, with bulk, CDC and HID personas, shipped as a documented demo device in the CLI. Add CLI end-to-end tests against it that run in the normal gate on all three OSes, and an opt-in hardware-in-the-loop (HIL) suite for the real meter. Base all behaviour on `docs/protocol.md` and our session-1 captures; never use the real serial or UID.

## Acceptance Criteria

- AC-G0W08Z.1: A `powerz-sim` workspace crate provides `SimDevice`, which implements `Transport`. It echoes request ids, answers 0x4C with id 0, puts the current auth level in reply header bits 17..18, and queues one stale DISCONNECT (`03 xx 00 00`) for the first read after open.
- AC-G0W08Z.2: ADC replies carry a 44-byte payload generated from the active scenario. Four named scenarios ship: `idle` (VBUS ≈ 0 V, IBUS ≈ 0 A), `load-5v-1a`, `pd-9v-2a` and `noisy-negative` (noisy current that goes negative); each defines VBUS/IBUS/CC/D± as functions of simulated time, and temperature stays between 25 and 35 °C.
- AC-G0W08Z.3: SETTINGS replies are 180 bytes whose block-A and block-B CRC-32 values verify with the library decoder, with the device name `POWER-Z` and the meter rate code in bits 2..3 of 0x60.
- AC-G0W08Z.4: Memory reads of the four allowed blocks return synthetic contents (model `KM003C`, firmware `2.0.6`, a made-up serial and UID) encrypted with the shipped key 0 using the real confirmation-plus-data reply shape; any other address gets REJECT.
- AC-G0W08Z.5: Auth at level 1 (UID) and level 2 (first 16 OTP bytes) succeeds through the library's `authenticate`, and a wrong credential is answered with level 0; 0x0E/0x0F/0x10/0x11 get REJECT below level 1, and 0x0E while a stream is running gets REJECT.
- AC-G0W08Z.6: The ADC queue always runs, at the meter rate (50 SPS) or at the rate set by 0x0E; records are produced in real (or injected) time with u32 ms timestamps, at most 63 per reply, oldest dropped on overflow, so a session that polls too slowly sees gaps.
- AC-G0W08Z.7: Fault injection can be enabled per device: reply timeouts, disconnect mid-stream, and replies with a wrong id; each fault surfaces through the library as the matching typed error or as a recovered stale reply.
- AC-G0W08Z.8: The CDC persona answers types 0x01/0x02/0x03 the way the meter does on CDC (ADCNEW framing is out of scope: they are answered with no reply) and otherwise behaves like bulk; the HID persona answers only single-report GET_DATA and returns `Error::Disconnected` (a simulated reboot) for any request whose reply would exceed 64 bytes, so the HID guard is exercised end to end.
- AC-G0W08Z.9: The CLI accepts `--transport sim` and `--scenario NAME` (default `idle`), shows both in `--help` as the "demo device", and `powerz list --include-demo` lists the simulator alongside real meters.
- AC-G0W08Z.10: `assert_cmd` tests run the real `powerz` binary against the simulator for `list --include-demo`, `info`, `read`, `read --json`, a bounded `watch`, and `stream --rate 50 --csv FILE --duration 2`, checking stdout, stderr and exit codes; the CSV test checks the header, a row count within ±5% of rate × duration, and integrated energy within 5% of the scenario's known value; human-readable `info` and `read` output is snapshot-tested with `insta`.
- AC-G0W08Z.11: Exit codes 2 (usage), 3 (no device), 4 (permission) and 5 (device error) are each produced end to end by a test, using simulator fault injection or arguments for 4 and 5.
- AC-G0W08Z.12: A HIL suite, ignored unless `POWERZ_HIL=1`, runs `list`, `info`, `read`, `read --json` and a 5-second `stream --rate 50` against the attached meter over bulk, using only the safe command set from `docs/protocol.md`; CI never sets the variable.
- AC-G0W08Z.13: The simulator crate contains no session-1 serial or UID (checked by the same digest scan as the protocol crate), and the sim e2e tests run in the normal gate, so CI runs them on Linux, macOS and Windows.

## Technical Design

New crate `crates/powerz-sim` depending on `powerz-protocol` (frame builders, crypto, decoders for self-checks). `SimDevice` holds state: auth level, stream rate, queue ring buffer, time source (real `Instant` or injected `SimClock`), scenario, persona and fault plan. The CLI depends on the sim crate and maps `--transport sim` to a `SimDevice` behind the same `Transport` trait, so every command path is shared. Snapshots via `insta`; output that changes over time is pinned by an injected clock or redacted.

## Testing

Unit tests in the sim crate per AC .1–.8 driving `SimDevice` through `powerz_protocol::session::Session`. CLI e2e tests in `crates/powerz-cli/tests/e2e_sim.rs` for AC .9–.11, snapshots under `tests/snapshots/`. HIL tests in `crates/powerz-cli/tests/hil.rs`, `#[ignore]` unless `POWERZ_HIL=1`. The digest scan covers the sim crate.
