# Offline records: list and download

## Summary

The meter can record measurements on its own, without a computer, and keeps up to 40 recordings.
This feature lists those recordings and downloads them to the computer.
A downloaded recording opens in the history chart and can be saved as CSV.
Nothing on the meter is changed or deleted.

## Requirement

The library, CLI and desktop app list the meter's offline recordings and download any of them read-only, decode their samples, and show and export them like a recorded session.

## Acceptance Criteria

- AC-1HHT00.1: The library reads the record list (GET_DATA 0x200, after level-1 auth) and decodes each 48-byte entry: name, interval, point count, duration, charge, energy and flash offset. An empty list (size 0) is not an error.
- AC-1HHT00.2: Download reads exactly one record's samples (point count × 16 bytes) from its flash offset through the memory-read path. The safe-read list gains only that window, computed from a decoded entry, bounded by the record area, and refused for any other address.
- AC-1HHT00.3: The 16-byte sample format is decoded from a recording made on the real meter, with the evidence written to the protocol docs. Until a field is confirmed it is marked inferred, and unknown fields are kept raw.
- AC-1HHT00.4: `powerz records list` prints the table and `powerz records get <n>|--all` writes CSV files in the existing recording layout; `--json` works for both.
- AC-1HHT00.5: The desktop app has a Records view: the list with the decoded columns, download of one or all with progress, and a downloaded record opens in the history chart with its statistics.
- AC-1HHT00.6: The simulator serves a record list and samples, so the CLI, desktop and e2e tests run without a meter.
- AC-1HHT00.7: No write, delete or settings command is sent; a test pins the exact commands the download sends.

## Technical Design

Decoder and download live in the protocol crate beside the memory reader; the window check reuses the existing safe-list guard with a computed range. The CSV writer and history model from the recorder are reused. The sample format is found by comparing a meter recording with its on-screen values and the record's charge and energy totals.

## Testing

Unit and property tests for the entry and sample decoders, simulator tests for list and download, CLI snapshot tests, and a desktop e2e test for the Records view. The real-meter check is in the hardware FR of this milestone.
