# An (i) beside the web device menu explains the connections

## Summary

The web edition reaches the meter in three ways, and the device menu does not explain them.
A small (i) button now sits next to that menu in the browser build.
Its popover says what WebUSB, HID and Web Serial each give.
It also names the browsers that can connect and the current connection.
The desktop app shows no such button.

## Requirement

In the web build, an info button beside the device menu explains what each browser connection gives, which browsers can connect, and what the current session uses.

## Acceptance Criteria

- AC-60QB2S.1: In the web build an (i) button sits right after the device menu; it is reachable by keyboard, has an accessible name, and follows the Show (i) icons switch like the other (i) buttons.
- AC-60QB2S.2: Pressing it opens a popover that behaves like the glossary popovers: one open at a time, a second press closes it, Escape or a click outside closes it and focus returns to the button.
- AC-60QB2S.3: The popover says, in short sentences: WebUSB gives the full feature set (live readings, PD capture, rates, records, logo); HID ("Connect over HID…") gives basic readings only and works even when another program holds the meter; Web Serial is used only for settings changes and the protocol trigger, and Chrome asks once for the meter's serial port.
- AC-60QB2S.4: The popover says that Chrome or Edge can connect, that Safari and Firefox show the demo only, and links to the desktop app download page.
- AC-60QB2S.5: The popover names the current session's connection: WebUSB, HID, the demo meter, or none yet.
- AC-60QB2S.6: The desktop and mock builds show no such button.
- AC-60QB2S.7: The top bar layout checks at 1280 and 1600 px still pass in WebKit and Chromium with the button in place.

## Technical Design

A pure helper builds the popover lines and the session line from the device listing and the HID flag. A small component pairs a glossary entry (term and short line, so the shared popover store, Escape and outside click stay the same) with that extra text, passed to the glossary popover as an optional child snippet. DevicePicker renders it only when the build's features are the web ones.

## Testing

Vitest for the helper and for the component rendered with svelte/server in web and desktop builds; one Playwright check in the web e2e suite that opens and closes the popover; the touched layout specs on WebKit and Chromium.
