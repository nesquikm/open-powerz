# Built-in open-powerz startup logos

## Summary

Two startup logos with the open-powerz mascot ship inside the CLI and the desktop app.
A user can put a logo on the meter without making an image first.
One shows the mascot surfing; the other adds the open-powerz lettering underneath.
The command line picks one by name instead of a file.
The desktop logo view offers them next to choosing a file.

## Requirement

The protocol library embeds the two brand meter logos, and both the CLI logo commands and the desktop logo view can use either one in place of an image file, with every existing guard unchanged.

## Acceptance Criteria

- AC-70X5YX.1: The library offers two built-in logos named surf and surf-wordmark, embedded in the build from the brand folder's meter logo PNGs; each encodes in the transparent mode to a 200×200 blob that the logo blob validator accepts, with 469 chunks.
- AC-70X5YX.2: The command line logo preview takes a built-in name in place of an image file and prints the same report as for a file, in the transparent mode, and with an output file writes the preview PNG; it opens no meter.
- AC-70X5YX.3: The command line logo write takes a built-in name in place of an image file and writes it with the same acknowledgement flag, typed confirmation, chunk and read-back progress, startup-duration report and menu-save wait as a file; the blob sent equals the built-in logo's encoding.
- AC-70X5YX.4: A built-in name and an image file together, or neither, is a usage error before any meter is opened; an unknown name is a usage error that lists the two names. A built-in logo always uses the transparent mode, and the transparent flag changes nothing for it.
- AC-70X5YX.5: The desktop logo view offers to use the open-powerz logo, with a choice between the mascot and the mascot with lettering; picking one shows its preview and sizes as a chosen file does, and Upload writes it through the same confirmation, progress, read-back and settings guidance.
- AC-70X5YX.6: While a built-in logo is picked, the view uses the transparent mode and the opaque option is disabled with a reason; choosing a file afterwards brings both modes back.
- AC-70X5YX.7: The demo meter accepts a built-in logo upload like a file upload, so the flow can be seen without a real meter.
- AC-70X5YX.8: The CLI reference, the user docs for the startup logo and the desktop backend reference describe the built-in logos and the new arguments.

## Technical Design

A built-in logo module in the library logo code: an enum with a name, a label and the embedded PNG bytes, a parser from the name and, behind the image-files feature, a loader. The CLI preview and write take an optional file and a builtin option, exactly one required. The desktop preview and upload commands gain an optional builtin argument that replaces the path. The logo store keeps a source that is a file path or a built-in name; the mock backend and demo meter accept both.

## Testing

Library unit tests encode both built-ins and validate the blobs. CLI integration tests on the simulator cover preview, write, the flag clashes and an unknown name. Rust command tests for the desktop preview and upload with a built-in name. Vitest for the store's source and mode lock; Playwright on Chromium and WebKit, with the wide font, for the picker and an upload on the demo meter.

## Notes

Depends on the brand kit FR for the PNGs. The transparent mode was proven on the real meter in stage 4 part B.
