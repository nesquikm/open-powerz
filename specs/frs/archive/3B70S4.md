# The zoom readout test compares against a stale span

## Summary

The end-to-end test of the zoom readout failed now and then on the Linux runner.
In the whole-session view the span keeps growing while the demo streams.
The test read the readout once, then waited for the slider to repeat that old value.
Now it reads both at the same moment and waits until they agree.

## Requirement

### Steps to reproduce
1. Run the timeline spec's zoom readout test on a busy runner.

### Expected
The test passes whatever the runner's speed.

### Actual
"Expected: 3:20, Received: 3:24" on the slider's spoken value (CI run 42769569733, ubuntu, chromium).

## Acceptance Criteria

- AC-3B70S4.1: Regression: in the whole-session view the test reads the visible readout and the slider's spoken value in one page evaluation and passes once the two are equal and the readout has the minutes-and-seconds shape.
- AC-3B70S4.2: The test's other checks (the 10 s readout, the shared tooltip, the position next to the slider) are unchanged.
- AC-3B70S4.3: The test passes 20 runs in a row locally on WebKit and on Chromium with one worker.

## Technical Design

### Root cause
The readout text was captured once, then the slider attribute was polled against that captured string while the whole-session span kept growing.

### Fix
Poll one evaluation that returns both strings and compare them inside it.

## Testing

The timeline spec test repeated 20 times with one worker on both browsers.
