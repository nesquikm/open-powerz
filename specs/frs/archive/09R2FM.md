# The connect hint shows in a browser that cannot connect

## Summary

Safari and other browsers without WebUSB and WebHID show a box saying the browser is not supported.
Next to the device menu it still showed the hint asking the user to pick the connect item.
Connecting cannot work there, so the hint points at a dead end.
Now the hint is hidden in such a browser, and the box alone explains it.

## Requirement

### Steps to reproduce
1. Open the web edition in Safari.
2. Look next to the device menu.

### Expected
No connect hint; the not-supported box explains what to do.

### Actual
The hint link 'Pick "Connect a meter…"' shows next to the menu (web HIL round 4, W9).

## Acceptance Criteria

- AC-09R2FM.1: Regression: in the web build, when the browser has neither WebUSB nor WebHID, the device picker shows no connect hint, even with only the demo meter listed.
- AC-09R2FM.2: In a browser with WebUSB or WebHID the hint still shows while only the demo meter is listed and goes away once a meter is listed, as before.
- AC-09R2FM.3: The WebKit end-to-end run on the built site sees the not-supported view and no connect hint, and the demo meter still streams.

## Technical Design

### Root cause
The hint shows whenever only the demo meter is listed; it never asks whether the browser can connect at all.

### Fix
In the device picker, hide the hint when the support probe on the navigator reports not supported, the same probe the app uses for the not-supported box.

## Testing

Vitest on the device picker with a navigator that has no usb or hid and one that has usb. The WebKit Pages spec checks the hint is absent.

## Notes

Reported as a minor by the web HIL round 4 (W9).
