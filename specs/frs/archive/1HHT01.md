# Meter settings, read-only

## Summary

The meter keeps its display and measurement settings in a 180-byte block.
This feature decodes that block and shows the settings in the command line tool and the desktop app.
It only reads; changing settings is a later milestone.
Each decoded field is checked against the meter's own screen.

## Requirement

The library decodes the settings block's known fields, and the CLI and desktop app show them read-only, with unknown or unconfirmed fields marked as such.

## Acceptance Criteria

- AC-1HHT01.1: The decoder checks both CRC-32 blocks and reports a mismatch instead of decoding.
- AC-1HHT01.2: It decodes language, brightness, dim timeout, rotation, auto-rotate, theme and sample rate per the research notes, and shows the calibration gains as raw read-only numbers. Every field carries a confirmed or inferred tag.
- AC-1HHT01.3: `powerz settings` prints the fields with their tags; `--json` and `--raw` (hex dump) work.
- AC-1HHT01.4: The desktop app shows a read-only Meter settings panel, refreshed on connect and on demand.
- AC-1HHT01.5: Each field the user can see on the meter is compared with a photo or reading of the meter's screen; a field that matches becomes confirmed in the docs, one that does not is fixed or stays inferred.
- AC-1HHT01.6: No settings write (type 0x0A) or SET_DATA is sent; a test pins the commands used.

## Technical Design

Extend the existing settings decoder in the protocol crate with typed fields and tags; the desktop panel reads it through the existing session. The bit positions and option labels come from the settings-dialog field map in the research control notes (§3.4). It corrects the feature inventory: theme is bits 16–18 of the first word. Unread bits stay raw. The same map also gives the startup-logo display time, so it is shown with an inferred tag.

## Testing

Unit tests on the captured 2.0.6 block and synthetic blocks (CRC failure, each field's range). Snapshot tests for the CLI output. A desktop component test for the panel.
