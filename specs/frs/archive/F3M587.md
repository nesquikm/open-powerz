# The web stream stops on the meter's empty queue reply

## Summary

The browser edition signs in to a real meter, but the stream stopped at the first poll.
The error was "truncated header at offset 4".
The meter had sent an empty reply that means nothing new yet.
The desktop app treats such a reply as no data, but the browser decoders treated it as broken.
The browser now reads empty and cut queue replies like the desktop app, tested against a realistic fake.

## Requirement

### Steps to reproduce
1. Build the web edition at 2060fb0 and open it in Chrome on macOS with a KM003C on the data port.
2. Connect a meter from the device menu and click Connect.

### Expected
Sign-in succeeds and readings stream, as in the desktop app.

### Actual
Sign-in and queue start succeed, then the page stops with "truncated header at offset 4" (web HIL run WEB.hil2-20261108-2223, W2 tries 2 and 3).

## Acceptance Criteria

- AC-F3M587.1: The ADC queue decoder returns no samples, and no error, for a PUT_DATA reply that is a bare 4-byte header at any auth level (for example the meter's 41 08 02 00 at level 1) and for a DISCONNECT reply.
- AC-F3M587.2: The ADC queue decoder keeps the whole records of a last queue section that is shorter than it declares and drops only the partial record, as the native session does; a cut section followed by another section still fails.
- AC-F3M587.3: The ADC snapshot decoder still fails on a reply with no ADC section, as the native session does; while the queue streams such a failure costs only the temperature and the stream goes on.
- AC-F3M587.4: A fake WebUSB meter that answers like the real KM003C (a stale frame waiting at open, auth level in every reply header after sign-in, the memory-read confirmation and its encrypted data in separate transfers, empty replies to the first queue and PD polls, queue replies above 64 bytes) runs the whole web session: sign-in, device info, ADC snapshot, the queue at each of the four rates and the PD sniffer, with no error.
- AC-F3M587.5: That fake is the default fake meter of the web driver session tests; the demo meter stays the fake of the demo tests only.
- AC-F3M587.6: Regression: with the fake of AC-F3M587.4 the first queue poll gets the empty level-1 reply and the stream keeps running; the same test fails before the fix.

## Technical Design

### Root cause
The native session reads one IN transfer per reply (a bulk read ends at a short packet), so replies are never split except the memory read, which the web driver already joins. Native get_data returns no sections for a header-only PUT_DATA or a DISCONNECT and keeps a cut last queue section. The wasm queue decoder walked sections on every PUT_DATA, so the empty reply failed reading a section header at offset 4.

### Fix
Route the wasm queue decoder through the same empty-reply and cut-queue rules as native get_data, and add the real-meter fake.

## Testing

Rust tests on the wasm decoders with byte vectors; Vitest over the real-meter fake through the web driver.

## Notes

The brief suspected split replies; the console log shows the reply was complete and empty.

## Hardware evidence (web HIL rounds 2 and 3)
