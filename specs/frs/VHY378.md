# Desktop device backend: picker, session worker and live streaming

## Summary

The desktop app gets a Rust backend that owns every meter connection.
It lists real meters and the demo device, connects, and streams measurements.
Samples reach the window in small batches, so the interface never stalls.
Unplugging keeps the data, a replug is detected, and errors read as plain advice.

## Requirement

Implement, in the desktop crate, a device manager and one session worker thread per connected meter on top of `powerz-protocol` and `powerz-sim`, exposed to the UI through Tauri commands and one IPC channel of backend events.

## Acceptance Criteria

- AC-VHY378.1: `list_devices` returns every attached meter (model, serial, USB bus/address) plus one "Demo device — <scenario>" entry for each simulator scenario (`idle`, `load-5v-1a`, `pd-9v-2a`, `noisy-negative`); listing never opens a device.
- AC-VHY378.2: `connect(device, rate)` opens the vendor bulk pipe on a dedicated worker thread, sends CONNECT, authenticates at level 1, starts the ADC queue at the requested rate (2, 10, 50 or 1000 SPS) and emits a `connected` status with model, firmware version and serial; `disconnect` stops the queue and closes the pipe; a second `connect` while a session is open is refused with a usage error.
- AC-VHY378.3: When authentication or the queue start is rejected, the worker keeps polling the queue at auth level 0 at the meter's own rate, emits `rate_locked: true` with the rate measured from record timestamps, and `set_rate` returns a "changing the rate needs authentication" error without sending any frame.
- AC-VHY378.4: Between queue polls the worker sends one ADC snapshot request at least once per second (never two requests in flight), and every batch carries the latest temperature in °C, or null when the meter reports it invalid.
- AC-VHY378.5: Samples reach the UI over one `tauri::ipc::Channel` in batches flushed at 20–60 Hz: streaming the demo device at 1000 SPS for 10 s of simulated time yields at most 600 batch messages, carrying every record exactly once in device-time order, with stream gaps sent as separate gap events.
- AC-VHY378.6: Unplugging the meter mid-stream ends the session with a `disconnected` status within 2 s and keeps every sample already received; the device list reflects a plug or unplug within 2 s; connecting the same serial again appends to the same session history, with a gap event marking the outage.
- AC-VHY378.7: Errors reach the UI as `{ kind, message, hint }` in plain language — permission denied (on Linux the hint names the udev rule from `docs/linux.md`), device busy or claimed by the kernel driver, timeout, and protocol error; no raw Rust error text or panic message is shown.
- AC-VHY378.8: Every request goes through the protocol crate's safety guard; a test records the frames sent during connect, rate change, snapshot polling and disconnect against the simulator and finds only frames from the safe command set in `docs/protocol.md`.

## Technical Design

New modules in the desktop crate: `devices` (discovery via `powerz_protocol::transport::discovery` plus simulator entries; hotplug by re-listing every 500 ms), `worker` (a thread owning `Session<GuardedTransport<T>>`, commands over an mpsc channel; its loop polls the queue at `Streamer::poll_period` and a snapshot every second), `batch` (a pure batcher flushing when 16.7 ms have passed with at least one sample, or at 50 ms), and `ui_error` (maps session and transport errors). The worker is generic over `Transport`, so tests use `MockTransport` and the simulator. Commands: `list_devices`, `connect`, `disconnect`, `set_rate`; events `Batch`, `Gap`, `Status`, `Error`.

## Testing

Unit tests for the batcher on an injected clock, the error mapping and the rate-fallback path against a mock that REJECTs auth. Worker integration tests against the simulator on its fake clock: batch count, ordering and no duplicates at 1000 SPS; a disconnect fault ends the session and keeps samples; the sent-frame log stays inside the safe set.

## Notes

Hotplug polls the device list instead of per-OS watch APIs; a native watcher can replace it later. The desktop app uses the bulk pipe only in this milestone; CDC and HID stay CLI-only.
