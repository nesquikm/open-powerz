# Measurement and settings decoders

## Summary

The meter reports voltage, current, temperature and data-line levels in packed binary records.
This feature turns those records into plain numbers in standard units.
It covers single readings, high-rate stream records, the settings block and device-info blocks.
Every decoder checks lengths and fails cleanly on short or odd input.

## Requirement

In `powerz-protocol`, add pure decoders for the ADC snapshot, ADC-queue records, the rate-code table, the SETTINGS block, and the device-info / OTP / UID memory blocks, in SI units, per `docs/protocol.md`.

## Acceptance Criteria

- AC-E88WR5.1: `AdcSnapshot::decode` accepts payloads of 40 or 44 bytes and returns VBUS, IBUS (signed), their averages and uncalibrated averages (µ-units ÷ 1e6 → V/A), temperature (i16 ÷ 128 → °C, `None` for 0x8000), CC1, CC2, D+, D− and VDD (÷ 10000 → V); on 44-byte payloads it also returns the active queue rate code from byte 0x26. Payloads shorter than 40 bytes return a decode error.
- AC-E88WR5.2: The captured firmware 2.0.6 ADC payload decodes to VBUS 0.004196 V, IBUS −0.000095 A, temperature 29.453125 °C, CC1 0.0805 V, CC2 0.0294 V, D+ 0.0724 V, D− 0.0754 V and VDD 3.2048 V.
- AC-E88WR5.3: `AdcSnapshot::power_w()` returns VBUS × IBUS, keeping the sign.
- AC-E88WR5.4: `QueueRecord::decode` reads 20-byte records: u32 device time in ms, VBUS and IBUS (÷ 1e6), and CC1, CC2, D+, D− scaled by the rate code: 0.1 mV units at code 0, 1 mV at codes 1–3. The captured code-2 record `1f4f0a00 b50f0000 c5ffffff 5200 1d00 4500 4400` decodes to t 675615 ms, VBUS 0.004021 V, IBUS −0.000059 A, CC1 0.082 V, CC2 0.029 V, D+ 0.069 V and D− 0.068 V.
- AC-E88WR5.5: `Rate` maps codes 0/1/2/3 to 2/10/50/1000 samples per second and back; `Rate::from_sps` rejects any other value, and code 4 is not representable.
- AC-E88WR5.6: `Settings::decode` takes the 180-byte payload and reports, separately for block A (bytes 0x00–0x5B against the u32 at 0x5C) and block B (0x60–0xAF against the u32 at 0xB0), whether the CRC-32 matches; it also returns the meter's rate code (bits 2..3 of the u32 at 0x60), the NUL-terminated device name at 0x70 and the raw bytes. The captured payload passes both CRCs with rate code 2 and name `POWER-Z`.
- AC-E88WR5.7: `DeviceInfoBlock::decode` reads the 64-byte info blocks (0x420, 0x4420) as four NUL-terminated ASCII strings at 0x10 (model), 0x1C (version), 0x28 (date) and 0x34 (extra), reporting "none" when the first u32 is 0xFFFFFFFF; `OtpBlock::serial()` returns the first space-separated token of the OTP block; `Uid` formats the 12-byte UID as hex.
- AC-E88WR5.8: A property test feeding 10 000 random byte strings to every decoder completes without a panic.

## Technical Design

Module `decode` with one submodule per record type and a shared `DecodeError`. Values are stored as raw integers with typed accessors returning `f64` SI units, so CSV export keeps full precision. CRC-32 via `crc32fast`. Info-block fixtures are synthetic: our own model/version strings and a made-up serial, laid out per the device log, so no real serial or UID enters the repo.

## Testing

Unit tests per decoder using the captured ADC payload, queue record and SETTINGS payload (frames with no identifying data), synthetic info/OTP/UID blocks, and a `proptest` property test for AC .8.

## Notes

The 0x24 temperature field read 0x8000 on every 2.0.6 sample, so it is decoded but not exposed as a second temperature. The settings gain arrays stay undecoded ([inferred]).
