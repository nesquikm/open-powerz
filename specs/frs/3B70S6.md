# Cancel cannot interrupt a large Open recording parse in the browser

## Summary

In the browser edition, opening a big recording file read the whole file in one go.
The page could not react to anything until the read was over, so Cancel did nothing until then.
Now the file is read in slices, and the page gets its turn between slices.
Cancel stops the read before the next slice, and the file that was open before stays open.

## Requirement

### Steps to reproduce
1. In the web edition, open a recording, then open a large CSV or .db recording.
2. Press Cancel while it reads.

### Expected
The open ends promptly and the earlier recording stays on screen.

### Actual
The page is frozen until the whole file is read; the cancel only takes effect afterwards (v0.12.0 known issue).

## Acceptance Criteria

- AC-3B70S6.1: Regression: a CSV recording is read in slices of at most 5,000 lines and a .db recording in slices of at most 5,000 rows, with a yield to the event loop between slices.
- AC-3B70S6.2: A Cancel during the read stops it before the next slice: the open ends as cancelled, no further slice is read, and the reader's memory is freed.
- AC-3B70S6.3: After a cancelled open, the recording open before it is still the one the range, statistics and close commands answer from.
- AC-3B70S6.4: An open that is not cancelled gives the same rows, skipped, left-out counts and statistics as before, for CSV and .db files, ours and the vendor's; its progress starts at nothing, never goes back and ends at the whole file (a CSV now also reports after each slice).

## Technical Design

### Root cause
The CSV goes through one synchronous wasm call and the .db loop never yields, so the Cancel click is only handled after the parse; the generation counter then discards the result.

### Fix
A wasm CsvRecording holds the bytes and a CSV reader and parses a given number of lines per call, reporting bytes read. The web reader takes an abort signal, steps the CSV or .db reader in slices, yields between them, and throws a cancel the open treats as cancelled.

## Testing

Rust tests for the stepped CSV reader against the one-shot reader; Vitest for slicing, cancel between slices, the kept earlier file and the unchanged results over the existing fixtures.

## Notes

v0.12.0 known issue from AHTZW3 (parity HIL 3 did not run Cancel).
