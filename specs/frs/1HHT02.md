# ADCNEW stream over the virtual serial port

## Summary

The meter can push measurements on its virtual serial port without being polled.
This feature adds that stream as a second way to read live measurements.
It needs no sign-in and shares the port with protocol triggering.
The command line tool and the desktop app can both use it.

## Requirement

The library decodes and drives the ADCNEW push stream on the CDC port, demultiplexed from PDM text and binary replies, and the CLI and desktop app can use it as a live measurement source.

## Acceptance Criteria

- AC-1HHT02.1: The decoder parses ADCNEW frames (4-byte header, body length in words, CRC-8 poly 0x29 over the body) and their 20-byte records; a bad CRC or length drops the frame and resynchronises.
- AC-1HHT02.2: The CDC reader separates ADCNEW frames, binary replies and PDM text lines on one byte stream, so the stream can run during a PDM text session.
- AC-1HHT02.3: Start picks content (ADC only first; PD and UFCS content kept raw) and rate, stop ends it, and the stream is refreshed before the meter's one-hour limit.
- AC-1HHT02.4: `powerz watch --source cdc` streams through it with the same output as the bulk path, and the desktop app offers it as a measurement source; the recorder and chart work unchanged.
- AC-1HHT02.5: On CDC, types 0x01, 0x02 and 0x03 are sent only as ADCNEW keep-alive, start and stop; their bulk meanings (SYNC, CONNECT, DISCONNECT) are never used there.
- AC-1HHT02.6: The simulator emits ADCNEW frames for tests.

## Technical Design

A stream decoder and a CDC demultiplexer in the protocol crate, beside the PDM text session. The measurement source abstraction gets a CDC variant; the recorder consumes the same records. A CDC session refuses records and the PD sniffer, whose requests were never checked on that port. Raw PD and UFCS frames are kept up to a fixed cap. For the hardware check, `powerz stream --source cdc` records the stream to CSV at 50 or 1000 records/s and prints records, gaps, dropped frames and CRC errors.

## Testing

Unit and property tests with recorded frames from the research vectors, demux tests with interleaved text, binary and stream bytes, and simulator end-to-end tests.
