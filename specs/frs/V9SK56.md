# Staged firmware checks on the real meter

## Summary

Firmware work on the real meter happens in three stages.
Each stage needs the user's explicit go-ahead at the time.
First the bootloader is only looked at, then the meter goes into the bootloader and back.
Only then is the 2.0.7 update flashed.
Each stage is run by a fresh test agent from a written runbook and recorded in the Notes.
The feature ships only if the full update has worked on the real meter.

## Requirement

The firmware features are checked on the real meter in three user-approved stages, ending with a successful update from 2.0.6 to 2.0.7, before the milestone ships.

## Acceptance Criteria

- AC-V9SK56.1: Stage 1, no writes: with the meter put into bootloader mode by hand, its USB identity, interfaces and mode string are recorded, CONNECT and HEAD are sent, and leaving the bootloader by unplugging is observed.
- AC-V9SK56.2: Stage 2: from application mode JUMP_DFU followed by a replug puts the meter into bootloader mode, and JUMP_APROM or a replug brings it back, with both recorded.
- AC-V9SK56.3: Stage 3: the 2.0.7 file from the research workspace is flashed with the desktop app or the CLI. The meter then reports 2.0.7 from its info block and on its About screen.
- AC-V9SK56.4: Each stage starts only after the user approves that stage in the conversation, and the approval and results are recorded in the Notes.
- AC-V9SK56.5: Each stage runs from a runbook written by the implementer and is carried out by a fresh test agent that runs only the runbook's commands and does not change code.
- AC-V9SK56.6: A read-only `powerz firmware probe` command shows the meter's USB identity (vendor and product IDs, product string, and each interface's class and interface string), then sends only CONNECT and HEAD and prints the HEAD field. It works in both application and bootloader mode, so stage 1 can use it. A SYNC reply means a bootloader left mid-download: the probe sends nothing more and tells the user to unplug the meter and hold Back while plugging it in.
- AC-V9SK56.7: A `powerz firmware jump --to bootloader|application --i-understand` command switches modes through the flash guard. From application mode it sends CONNECT, the UID read and the level-1 0x4C authentication, then JUMP_DFU; a failed authentication stops before JUMP_DFU. From bootloader mode it sends only JUMP_APROM. It reports the meter's reply to the jump (ACCEPT, REJECT, another type or none), asks the user to replug the meter if it does not restart by itself, then reports the mode the meter comes back in. Stage 2 uses it.
- AC-V9SK56.8: Every `powerz firmware` subcommand that talks to a meter (`probe`, `jump`, `flash`) honours `--trace`: each frame it sends and receives, raw writes included, is written to stderr.

## Technical Design

One runbook per stage: preconditions (meter on a stable port, laptop on power), the exact commands, expected outputs, abort criteria and recovery steps.

## Testing

The probe command has unit and simulator tests. The stages themselves are hardware only and record results rather than adding automated tests.

## Notes

Stages lift safety rules only with user approval.

An early descriptor ACK broke run 2 and erased the app. Bootloader screens: "firmware details" with an app, blank with a blinking green bar without.
