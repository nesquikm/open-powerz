# Several meters at once

## Summary

People who test chargers often use two meters side by side.
The desktop app can now connect to several meters at the same time and show them in a grid.
Each meter has its own readout, chart and recording.
The simulator stands in for a second meter in tests.

## Requirement

The desktop app connects to more than one meter at a time, each with an independent session, readout, chart and recorder, and lays them out in a grid.

## Acceptance Criteria

- AC-1HHT03.1: The device picker can add a second (and further) meter; each connected meter runs its own session and measurement stream.
- AC-1HHT03.2: The main view shows one tile per meter in a responsive grid (two columns on a wide window), each with its name, serial suffix and live readout; one tile can be expanded to the full single-meter view.
- AC-1HHT03.3: Recording, replug recovery and the PD, trigger and firmware views stay per meter, and an action never goes to a meter other than the one its tile belongs to.
- AC-1HHT03.4: Unplugging one meter leaves the others running.
- AC-1HHT03.5: The CLI keeps its single-device commands; `--device` selection works for every command that talks to a meter.
- AC-1HHT03.6: e2e tests run two simulated meters together.

## Technical Design

The backend keeps a map of sessions keyed by device id instead of a single slot; commands and events carry the device id. The frontend keeps per-device stores and a grid layout component.

## Testing

Backend tests with two simulated devices, frontend store tests, and a Playwright test with two simulators. With one real meter on hand, the hardware check pairs it with the simulator.

## Notes

Single-meter use must look and behave exactly as before.
